# 输入输出格式说明

本文件描述 OSMOSIS 的输入数据格式、输出产物格式与输出目录结构。

---

## 1. 任务与像素约定

**主任务：球体分割（二值）**

| 项           | 约定                                                                             |
| ------------ | -------------------------------------------------------------------------------- |
| 正类         | 球体区域                                                                         |
| 背景         | 芯片区域                                                                         |
| 真值编码     | `uint8` 二值图，**0 = 芯片/背景，1 = 球体**                              |
| 预测输出     | 概率图 → 阈值`SEG_THRESHOLD`（默认 0.5）→ 二值掩码，255 = 球体               |
| 类别极不均衡 | 前景（球体）像素占比约 11%；损失用`BCE + soft Dice`（`SEG_LOSS='bce_dice'`） |

---

## 2. 输入格式

### 2.1 图像读法

三个阶段读三类完全不同的图像，通道与几何各不相同。

| 阶段 | 图像                 | 通道读法                                          | 几何（训练 / 评估）                                                                       |
| ---- | -------------------- | ------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 1    | RxRx1 荧光 PNG       | 6 通道取 3 通道，各`convert('L')` 后堆叠，非RGB | `RandomResizedCrop(512, scale=(0.2, 1.0))` / 短边 585 + 中心裁剪 512                    |
| 2    | OoC 明场 PNG         | `convert('RGB')`，单通道复制成 3 通道           | `RandomResizedCrop(512, scale=(0.8, 1.0))` + 0.5 概率水平翻转 / 短边 585 + 中心裁剪 512 |
| 3    | HTS-Seg 芯片`.bmp` | `convert('RGB')`，单通道复制成 3 通道           | 整图双线性缩放到 512×512（`antialias=True`）                                           |

#### Stage 1 — RxRx1（`data/rxrx1.py`）

- 通道：`RXRX1_CHANNELS = [0, 1, 4]`，即文件名里的 `w1`（Hoechst，细胞核）、`w2`（ConA，内质网）、
  `w5`（Phalloidin，肌动蛋白）；三个平面各按 `convert('L')` 读取后堆叠成 3 通道。
- 缓存：`prepare_rxrx1_cache.py` 把像素预解码成 `rxrx1_ch0-1-4_s256.u8`（uint8 memmap，
  `(N, 3, 256, 256)`）+ 同名 `.json`。注意缓存边长 256 而网络输入 512，等于先
  降采样再增强放大。
- 缺文件：单个通道缺失用全 0 平面兜底，不中断训练。
- 增强：仅 `RandomResizedCrop`，无翻转、无颜色扰动。

#### Stage 2 — OoC（`data/ooc.py`）

- 通道：`convert('RGB')`，单通道图被复制成 3 通道。
- 几何：训练 `RandomResizedCrop(512, scale=(0.8, 1.0), ratio=(3/4, 4/3))` + 0.5 概率水平翻转；
  评估短边缩到 585，再中心裁剪 512。OoC 原图尺寸不统一（实测有 1536×2048、1542×2056），
  每一条分支都必须输出固定 `(512, 512)`，否则 `collate` 直接报错。
- 标签：`good` = 0 / `bad` = 1，只在辅助分类分支（`DOM_AUX_CLS`）使用；域适应本身无监督。

#### Stage 3 — HTS-Seg（`data/hts.py`）

- 扩展名：`.bmp` / `.png` / `.jpg` / `.jpeg` / `.tif` / `.tiff`
  （实际数据里图像是 `.bmp`、掩码是 `.tif`）。
- 几何：整张 tile 直接双线性缩放到 512×512（`antialias=True`），不做中心裁剪。掩码覆盖整张
  tile，图像与掩码用同一套几何。
- 掩码：`.tif` → `convert('L')` → `NEAREST` 缩放到同一尺寸 → `> 0` 严格二值化（0 = 芯片，1 = 球体）。掩码用 `NEAREST`。
- 增强：仅水平翻转 / 垂直翻转 / 90° 整数倍旋转，图像、掩码、距离图严格同步。
- 推理与训练同口径：RGB → 整图双线性缩放，无 center crop。

### 2.2 数据集目录布局

#### Stage 1 — RxRx1

```
{RXRX1_ROOT}/                                     # .../rxrx1-images/images
└── {experiment}/Plate{plate}/{well}_s{site}_w{channel}.png     # channel = 1..6
```

- 样本清单由 `RXRX1_METADATA`（`metadata.csv`）的 experiment / plate / well / site 四列拼出路径。
- 默认只取 `dataset == 'train'` 的 site，`RXRX1_SUBSET_RATIO` 可再按比例取子集。

#### Stage 2 — OoC

```
{OOC_ROOT}/
├── train/{good,bad}/cell_type_*/{0-1,2-3,4,4+}_days/*.png
├── val/{good,bad}/...
└── test/{good,bad}/...
```

- 递归：图像位于 `cell_type_*` / `*_days` 两层之下。
- 共 3,072 张。`OOC_SPLITS_FOR_DOMAIN` 域适应无监督默认 `['train', 'val', 'test']` 三个全用。

#### Stage 3 — HTS-Seg

```
{HTS_ROOT}/{tiled_images | cleaned_tiled_images}/
├── images/
│   ├── control/*.bmp        # 未处理组
│   └── treatment/*.bmp      # 药物处理组
└── labels/
    ├── control/*.tif        # 与 images/control 同名同数
    └── treatment/*.tif
```

- `HTS_SUBSET` 默认 `cleaned_tiled_images`（2,180 张，已剔除伪影）；`tiled_images` 是论文口径的 2,971 张。
- `images/**` 与 `labels/**` 的文件数量必须相等，且按 basename（去扩展名）能一一配对；
  代码会显式断言，不满足报错。
- `control/` 与 `treatment/` 两个子目录名不可更改：样本的组别标签由路径推断
  （路径中含 `/treatment/` 记为 1，否则记为 0），写入 `label` 字段。
- 划分：递归列出后按路径排序，再用
  `sklearn.train_test_split(test_size=TEST_RATIO, random_state=SPLIT_SEED)` 切测试集，
  再对剩余部分切出 `VAL_RATIO` 作验证集。复刻 baseline notebook 的划分方式，
  默认 subset 下测试集 436 张，与 baseline 论文一致，指标可直接对比。
- `SEG_SPLIT_MODE` 可改 `condition` / `condition_rev`：训练集只用 `control/`、测试集只用
  `treatment/`，用于测药物处理造成的分布偏移。

## 3. 输出格式

### 3.1 输出目录结构

三级嵌套目录（下游嵌在上游之下，因为下游依赖上游导出的 `encoder.pt`）：

```
{OUTPUT_ROOT}/                              ← {_ROOT_BASE}/<split-tag>/
├── _cache/
│   ├── filelists/files_<md5[:16]>.json      # 目录清单缓存（避免在 NFS 上反复 rglob）
│   ├── component_analysis.json              # analyze_components.py 产物
│   ├── gt_analysis.json                     # analyze_gt.py 产物
│   └── distmaps/<stem>.npy                  # 边界损失的 GT 距离图缓存（用 SEG_LOSS 含 bnd 时）
├── batch_size_probe.json                    # probe_memory.py 产物（探显存定 batch）
├── summary/
│   ├── report.md                            # report.py 汇总（含三阶段曲线索引）
│   ├── curves/{stage1_loss,stage2_domain,stage3_seg}.png
│   ├── ensemble.json                        # eval_ensemble.py 产物（集成 + 逐模型）
│   ├── ens_probs/{model*.npy, gt.npy, ensemble.npy}   # --dump-probs 时
│   ├── compare_runs.{md,json}               # compare_runs.py 产物
│   ├── sig_test_*.json                      # sig_test.py 产物（配对检验）
│   ├── external/*.json                      # eval_external.py 产物
│   └── FINAL_RESULTS.md                     # final_summary.py 产物
├── s1-…/                                     ← Stage 1 目录（train_mae.py 的输出根）
│   ├── ckpt/{last.pt, best.pt, step_<step:08d>.pt}
│   ├── encoder.pt                            # ★ 下游加载的就是它
│   ├── encoder_full.pt                       # 仅当 MAE_SAVE_DECODER=True
│   ├── train_log.jsonl
│   ├── metrics.json
│   └── config_snapshot.py                    # 该次运行的完整 config 快照（复现关键）
│   └── s2-…/                                 ← Stage 2 目录（嵌在 s1 下）
│       ├── ckpt/{last.pt, best.pt, step_*.pt}
│       ├── encoder.pt                        # ★ 域适配后的编码器
│       ├── train_log.jsonl
│       ├── metrics.json
│       ├── config_snapshot.py
│       └── s3-…/                             ← Stage 3 目录（嵌在 s2 下）
│           ├── ckpt/{last.pt, best.pt, step_*.pt}
│           ├── train_log.jsonl
│           ├── metrics.json
│           ├── config_snapshot.py
│           ├── split_meta.json               # 本次划分（不含 test_stems）
│           ├── test_summary.json             # AUTO_EVAL_AFTER_TRAIN=True 时
│           ├── eval/
│           │   ├── test_metrics.json         # ★ 测试集全套指标（含逐图向量）
│           │   ├── table2.md                 # 与 baseline 论文 Table 2 对齐的对照表
│           │   ├── test_predictions.npz      # gt / pred / labels / probs 四组数组
│           │   ├── test_split_meta.json
│           │   ├── eval_log.jsonl
│           │   └── figures/qualitative.png   # 原图 / GT / 预测 三联图
│           └── eval_tta/                     # eval_tta.py 产物
│               ├── summary.json, threshold_scan.json
│               ├── test_probs.npz
│               └── eval_tta_log.jsonl
```

各段目录名（`<split-tag>`、`s1-…`、`s2-…`、`s3-…`）的定义见 `config.py`
的 `_split_tag` / `_stage1_tag` / `_stage2_tag` / `_stage3_tag`，每个参数都有中文注释。
用 `python -c "import config; print(config.OUTPUT_ROOT, config.DIR_STAGE3)"` 可随时打印当前配置对应的路径。

### 3.2 `train_log.jsonl` —— 日志记录格式

一行一个 JSON 对象，由 `utils.Logger` 追加写入（`buffering=1`，同时回显到 stdout）：

```json
{"time": "YYYY-mm-dd HH:MM:SS", "msg": "<事件名>", "<字段1>": ..., "<字段2>": ...}
```

`msg` 是事件名，其余是随事件变动的字段。

Stage 3 的记录序列：

| `msg`                                              | 触发时机                               | 字段                                                                                                                                                                                            |
| ---------------------------------------------------- | -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Stage3 启动`                                      | 训练开始                               | `subset, n_total, n_train, n_val, n_test, img_size, device`                                                                                                                                   |
| `载入编码器权重: <path> (missing=N, unexpected=M)` | 载入上游编码器                         | 字段在 msg 字符串里                                                                                                                                                                             |
| `模型就绪`                                         | 模型构建完成                           | `trainable, encoder_from, frozen_layers`                                                                                                                                                      |
| `损失函数`                                         | 损失确定                               | `loss, pos_weight, dice_weight`                                                                                                                                                               |
| `已恢复断点` / `未发现断点，从零开始`            | 断点处理                               | `path, epoch, step, best`                                                                                                                                                                     |
| `早停已启用`                                       | 早停配置                               | `patience, min_delta, mode, judge`                                                                                                                                                            |
| `train`                                            | 每`LOG_EVERY_STEPS` 步               | `epoch, step, loss, lr, sec_per_step, mem`                                                                                                                                                    |
| `epoch 结束`                                       | 每轮验证后                             | `epoch, val_fg_dice, val_jaccard, val_accuracy, val_assd, val_hd95, val_biou2, best, is_best, es_score, es_best, bad_epochs, mem`                                                             |
| `早停触发`                                         | 触发早停                               | `epoch, bad_epochs, patience, min_delta, best_val_fg_dice`                                                                                                                                    |
| `Stage3 训练完成`                                  | 训练收尾（=`metrics.json` 全部字段） | `stage, epochs_done, global_step, best_val_fg_dice, es_best, n_train, n_val, n_test, subset, batch_size, encoder_from, peak_gpu_gb, oom_skipped_steps, best_ckpt, interrupted, early_stopped` |
| `开始测试集评估`                                   | 自动评估开始                           | —                                                                                                                                                                                              |
| `test 评估`                                        | 评估完成（由`eval_seg.py` 打出）     | `n, precision, recall, dice, jaccard, accuracy`                                                                                                                                               |
| **`测试集结果`**                             | 训练脚本收尾                           | **`precision, recall, dice, jaccard, accuracy`**（各 4 位小数）                                                                                                                         |

最后`测试集结果`，例如：

```json
{"time": "2026-09-19 01:09:05", "msg": "测试集结果", "precision": 0.9518, "recall": 0.953, "dice": 0.9845, "jaccard": 0.9697, "accuracy": 0.9843}
```

Stage 1 / Stage 2 的记录序列见 `train_mae.py` / `train_domain.py` 里的 `log.log(...)` 调用，
字段含义（`loss` / `recon_src` / `recon_tgt` / `domain` / `dom_acc` …）在各自函数内注释。
`report.py` 按 `msg` 与字段名解析这些日志，字段名具有依赖，不支持直接改名。

```json
}
```

**`{DIR_STAGE3}/eval/test_metrics.json`** — 更完整，多出 pooled 口径、边界指标、对照表：

```json
{
  "split": "test",
  "metrics": {"n_images": 436,
              "per_image": { ...同上... },
              "pooled": { ...把 436 张的像素堆在一起算的口径... }},
  "boundary": {"assd": {...}, "hd95": {...}, "hd": {...},
               "biou2": {...}, "biou5": {...}, "biou10": {...}},
  "boundary_by_size": {"<指标>": {"small": [mean, std], "medium": [...], "large": [...]}},
  "vs_baseline": {"model": ..., "reference": "DeepLabv3", "rows": [...]},
  "baseline_table2": { ...5 个 baseline 的论文原值... }
}
```

**`{DIR_STAGE3}/metrics.json`** — 训练摘要，字段与 `Stage3 训练完成` 那条日志完全相同。

**`{DIR_STAGE3}/split_meta.json`** — `{subset, image_dir, img_size, n_total, n_train, n_val, n_test, split_seed, test_ratio, test_labels}`。`test_stems`（436 个文件名）被显式剔除，
以免泄漏测试集清单到结果目录。

**`{DIR_STAGE3}/config_snapshot.py`** — 该次运行 import 时的 `config.py` 全文副本。
复现凭据：后续即使 `config.py` 默认值变了，也能从快照还原当时的全部超参。

### 3.4 推理脚本的输出格式

`inference.py` 的输出（格式与训练真值同约定）：

```
<out>/
├── masks/<stem>.png      二值掩码，uint8，255 = 球体，0 = 背景
├── probs/<stem>.npy      float16 概率图，shape (H, W)，仅 --save-prob 时
└── predictions.json      {"ckpt", "threshold", "tta", "img_size", "decoder",
                           "n_images", "records": [{"image","stem","fg_fraction",
                           "prob_max", 可选 "gt" 与五项指标}],
                           可选 "metrics_vs_gt": {"<指标>": {"mean","std"}}}
```

`evaluate.py` / `test_script.py` 的输出 JSON 结构：

```json
{
  "split": "test", "ckpts": [...], "n_models": 3, "tta": true,
  "img_size": 512, "decoder": "bilinear", "split_seed": 42,
  "subset": "cleaned_tiled_images", "n_images": 436,
  "threshold": 0.48, "threshold_source": "val:biou2",
  "per_model": [ {"tag": "model0", "threshold": 0.5,
                  "region": {"precision","recall","dice","jaccard","accuracy"},
                  "region_fg_dice": 0.9545,
                  "boundary": {"assd","hd95","hd","biou2","biou5","biou10"},
                  "boundary_by_size": {...}, "ckpt": "...", "seconds": 412.3}, ... ],
  "result": {"tag": "ensemble", "threshold": 0.48,
             "region": {...}, "region_fg_dice": ...,
             "boundary": {...}, "boundary_by_size": {...}},
  "per_image_vectors": {"dice": [...436...], "jaccard": [...],
                        "fg_dice": [...], "assd": [...], "hd95": [...]},
  "labels": [0, 1, ...]
}
```

`per_image_vectors` 是逐图配对检验（`sig_test.py`）的输入，`labels` 是 control/treatment。
